# Phase 2 — Build `@metriclink/common`

### What we are building in this phase

`@metriclink/common` is the **shared infrastructure package** for MetricLink.io. It will contain utilities that multiple services can consume without duplicating implementation.

For this phase, we will build only two shared capabilities:

```text
@metriclink/common
│
├── Logger
│   └── createLogger()
│
└── Environment
    └── createEnv()
```

The dependency relationship is intentional:

```text
zod ──────→ createEnv()
pino ─────→ createLogger()
                ↓
          @metriclink/common
                ↓
       auth / url / analytics / gateway
```

We will use **MetricLink names throughout**, not the old HiFive names.

# 2.1 — Initialize `@metriclink/common`

## 1. What we're doing right now

We are turning `packages/common` into a real workspace package and installing the two dependencies required by its shared functionality: **Zod** for validation and **Pino** for logging.

## 2. Why this has to happen at this exact point

Nothing inside `common` can be implemented correctly until the package exists and its runtime dependencies are declared.

We install both now because both are part of the **public purpose of this package**: services will eventually import `createLogger()` and `createEnv()` from `@metriclink/common`.

## 3. Actual command

From the repository root:

```bash
cd packages/common

pnpm init

pnpm add zod pino
```

You can verify the installed versions with:

```bash
pnpm list zod pino
```

Now configure `packages/common/package.json`:

```json
{
  "name": "@metriclink/common",
  "version": "1.0.0",
  "private": true,
  "description": "Shared infrastructure and utilities for MetricLink.io",
  "packageManager": "pnpm@11.9.0",

  "main": "./dist/index.js",
  "types": "./dist/index.d.ts",

  "type": "module",

  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    }
  },

  "files": [
    "dist"
  ],

  "scripts": {},

  "keywords": [],
  "author": "",
  "license": "ISC",

  "dependencies": {
    "pino": "^10.3.1",
    "zod": "^4.4.3"
  }
}
```

### Understanding the important fields

| Field          | Purpose                                                                    |
| -------------- | -------------------------------------------------------------------------- |
| `name`         | Workspace package identifier used by services such as `@metriclink/common` |
| `private`      | Prevents accidental publishing                                             |
| `main`         | Legacy/general entry point for compiled runtime code                       |
| `types`        | Legacy/general TypeScript declaration entry point                          |
| `type: module` | Makes the package use native ESM semantics                                 |
| `exports`      | Defines the supported public import interface                              |
| `files`        | Restricts packaged contents to `dist`                                      |
| `dependencies` | Runtime dependencies required by the package                               |

The important architecture is:

```text
Service
   │
   │ import { createLogger } from "@metriclink/common"
   ↓
exports["."]
   │
   ├── types  → dist/index.d.ts
   └── import → dist/index.js
```

The `.js` extension in:

```json
"import": "./dist/index.js"
```

is important because we're using Node's ESM/`NodeNext` module system.

## 4. What to check

From the repository root:

```bash
pnpm list --filter @metriclink/common
```

Then:

```bash
pnpm --filter @metriclink/common list zod pino
```

You should see:

```text
@metriclink/common
├── pino
└── zod
```

Also confirm:

```bash
cat packages/common/package.json
```

and verify the package name is:

```text
@metriclink/common
```

**Do not create `logger.ts` yet if this check has not passed.**

Once this passes, we'll build the **logger**, because Pino is now available and the package has a defined public entry point.
