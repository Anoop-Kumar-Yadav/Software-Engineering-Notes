

We now formalize the recursion-tree reasoning from the previous topic.

The **Master Theorem** is specifically designed for recurrences of the form:

[  
T(n)=aT(n/b)+f(n)  
]

This appears whenever an algorithm:

1. Creates `a` recursive subproblems.
    
2. Each subproblem has size approximately `n/b`.
    
3. Performs `f(n)` work outside those recursive calls.
    

The important thing is that the theorem is not a separate concept from recursion trees. **It is a compressed way of analyzing the same recursion tree.**

---

## 1. First understand the recurrence structure

Consider:

```text
T(n) = 2T(n/2) + n
```

Interpret every part mechanically:

```text
2T(n/2)
│ │   │
│ │   └── each child has size n/2
│ └────── recursive call
└──────── two children
```

And:

```text
+n
```

means the current function performs `O(n)` additional work.

So the recursion looks like:

```text
                         n
                    /         \
                  n/2         n/2
                 /  \         /  \
               n/4  n/4     n/4  n/4
```

Every internal node also performs local work.

---

# 2. The critical quantity

For:

[  
T(n)=aT(n/b)+f(n)  
]

calculate:

[  
n^{\log_b a}  
]

This quantity represents the approximate growth of the **recursive tree itself**.

Why?

At depth `k`:

```text
number of nodes = a^k
```

The recursion stops when:

[  
\frac{n}{b^k}=1  
]

Therefore:

[  
k=\log_b n  
]

At the final level:

[  
a^{\log_b n}  
]

Using the logarithm identity:

[  
a^{\log_b n}=n^{\log_b a}  
]

So:

> **`n^(log_b a)` represents the asymptotic amount of recursive work generated by the tree's branching structure.**

We then compare that against:

[  
f(n)  
]

the local work performed at each invocation.

---

# 3. The three Master Theorem cases

For:

[  
T(n)=aT(n/b)+f(n)  
]

define:

[  
c=\log_b a  
]

and compare:

[  
f(n)  
]

with:

[  
n^c  
]

There are three major cases.

|Case|Comparison|Result|
|---|---|---|
|1|`f(n)` grows slower than `n^c`|`Θ(n^c)`|
|2|`f(n)` grows at same rate as `n^c`|`Θ(n^c log n)`|
|3|`f(n)` grows faster than `n^c`|`Θ(f(n))`|

The most important skill is **not memorizing the table**.

You should understand _why_ each case occurs.

---

# 4. Case 1 — Recursive tree dominates

Consider:

[  
T(n)=2T(n/2)+1  
]

Here:

```text
a = 2
b = 2
f(n) = 1
```

Calculate:

[  
\log_2 2=1  
]

Therefore:

[  
n^{\log_2 2}=n  
]

Now compare:

```text
recursive growth → n

local work → 1
```

The recursive tree is much larger.

Therefore:

[  
T(n)=\Theta(n)  
]

---

## 4.1 Visualize the tree

```text
                         n
                    /         \
                  n/2         n/2
                 /  \         /  \
               n/4  n/4     n/4  n/4
              / \    / \    / \    / \
             ...
```

Every node performs only:

```text
O(1)
```

work.

But the final level contains approximately:

```text
n
```

nodes.

Therefore the total work is:

```text
O(n)
```

The **leaves dominate**.

---

# 5. Example: `T(n) = 4T(n/2) + 1`

Now:

[  
T(n)=4T(n/2)+1  
]

We have:

```text
a = 4
b = 2
f(n) = 1
```

Calculate:

[  
\log_2 4=2  
]

Therefore:

[  
n^{\log_2 4}=n^2  
]

Compare:

```text
recursive growth → n²
local work → 1
```

Recursive work dominates.

Therefore:

[  
\boxed{T(n)=\Theta(n^2)}  
]

The recursion tree has:

```text
level 0 → 1 node
level 1 → 4 nodes
level 2 → 16 nodes
level 3 → 64 nodes
...
```

At the leaf level there are approximately:

```text
n²
```

nodes.

---

# 6. Case 2 — Recursive and local work are equal

Consider merge sort:

[  
T(n)=2T(n/2)+n  
]

We already calculate:

[  
n^{\log_2 2}=n  
]

Local work:

[  
f(n)=n  
]

Therefore:

```text
recursive growth = n
local work       = n
```

They are asymptotically equal.

This produces an additional `log n` factor:

[  
\boxed{T(n)=\Theta(n\log n)}  
]

---

# 7. Why does `log n` appear?

This is much more important than memorizing Case 2.

The recursion tree looks like:

```text
                    n
                 /     \
               n/2     n/2
              /  \     /  \
            n/4  n/4 n/4  n/4
              ...
```

At every level:

```text
total work = n
```

The depth is:

```text
log n
```

Therefore:

[  
n+n+n+\cdots+n  
]

for `log n` levels.

Thus:

[  
n\log n  
]

So Case 2 is really saying:

> **Every level contributes approximately the same amount of work, and there are logarithmically many levels.**

---

# 8. Another Case 2 example

Consider:

[  
T(n)=9T(n/3)+n^2  
]

Calculate:

```text
a = 9
b = 3
```

Therefore:

[  
\log_3 9=2  
]

So:

[  
n^{\log_3 9}=n^2  
]

Local work:

[  
f(n)=n^2  
]

They are equal.

Therefore:

[  
\boxed{T(n)=\Theta(n^2\log n)}  
]

The recursion tree interpretation is:

```text
level 0 → n²
level 1 → n²
level 2 → n²
...
```

with:

```text
log₃ n
```

levels.

Hence:

```text
n² × log n
```

---

# 9. Case 3 — Local work dominates

Consider:

[  
T(n)=2T(n/2)+n^2  
]

Calculate:

[  
n^{\log_2 2}=n  
]

Compare:

```text
recursive growth → n

local work → n²
```

Local work grows faster.

Therefore:

[  
\boxed{T(n)=\Theta(n^2)}  
]

---

# 10. Why does the root dominate?

Draw the tree.

Root:

```text
n²
```

Second level:

```text
2 × (n/2)²
```

which becomes:

[  
\frac{n^2}{2}  
]

Third level:

```text
4 × (n/4)²
```

which becomes:

[  
\frac{n^2}{4}  
]

Therefore:

```text
n²
n²/2
n²/4
n²/8
...
```

The total is:

[  
n^2\left(1+\frac12+\frac14+\frac18+\cdots\right)  
]

The geometric series converges to a constant.

Therefore:

[  
\Theta(n^2)  
]

The **upper levels dominate**.

# 12. Let's analyze real algorithms

Now let's stop treating this as mathematics alone.

## Binary Search

Binary search:

```text
T(n) = T(n/2) + O(1)
```

Here:

```text
a = 1
b = 2
```

Calculate:

[  
n^{\log_2 1}=n^0=1  
]

And:

```text
f(n) = 1
```

They are equal.

Therefore:

[  
T(n)=\Theta(\log n)  
]

This is Case 2.

Notice something interesting:

The base complexity is:

```text
n^0 = 1
```

and the additional tree depth gives:

```text
log n
```

Hence:

```text
O(log n)
```

---

# 13. Merge Sort

```text
T(n) = 2T(n/2) + O(n)
```

Calculate:

[  
n^{\log_2 2}=n  
]

Local work:

[  
n  
]

Same.

Therefore:

[  
\boxed{O(n\log n)}  
]

---

# 14. Quicksort — balanced case

If partitioning produces approximately equal halves:

```text
T(n) = 2T(n/2) + O(n)
```

Therefore:

[  
O(n\log n)  
]

This is why balanced quicksort is efficient.

---

# 15. Quicksort — worst case

Suppose the pivot produces:

```text
0 elements left
n-1 elements right
```

The recurrence becomes:

[  
T(n)=T(n-1)+O(n)  
]

This is **not a Master Theorem recurrence**.

Why?

Because the recursive problem is:

```text
n-1
```

rather than:

```text
n/b
```

The Master Theorem requires the recursive subproblem to shrink by a **constant factor**.

So:

```text
T(n) = 2T(n/2) + n
```

fits.

But:

```text
T(n) = T(n-1) + n
```

doesn't.

This limitation is important.

---

# 16. Master Theorem does not solve every recursion

Do not blindly apply it.

It works for structures resembling:

```text
T(n) = aT(n/b) + f(n)
```

It does not directly apply to:

```text
T(n) = T(n-1) + 1
```

or:

```text
T(n) = T(n-1) + T(n-2)
```

or:

```text
T(n) = T(n/2) + T(n/3) + n
```

or many recurrences involving irregular subproblem sizes.

For those, use:

```text
recursion tree
```

or:

```text
expansion / substitution
```

or more advanced recurrence techniques.

---

For an applicable recurrence:

[  
T(n)=aT(n/b)+f(n)  
]

follow this exact procedure.

### Step 1

Identify:

```text
a
b
f(n)
```

### Step 2

Calculate:

[  
c=\log_ba  
]

### Step 3

Calculate:

[  
n^c  
]

### Step 4

Compare:

```text
f(n)
```

against:

```text
n^c
```

### Step 5

Determine the case.

```text
f(n) smaller
    ↓
Case 1

f(n) same
    ↓
Case 2

f(n) larger
    ↓
Case 3
```


[

]

The depth is:

[

# 20. A deeper understanding of `n^(log_b a)`

This expression should no longer look mysterious.

Suppose:

```text
a = 3
b = 2
```

Every recursion level:

```text
problem size halves
```

but:

```text
number of problems triples
```

So:

```text
Depth 0 → 1 problem
Depth 1 → 3 problems
Depth 2 → 9 problems
Depth 3 → 27 problems
...
```

At the same time:

```text
Depth 0 → n
Depth 1 → n/2
Depth 2 → n/4
Depth 3 → n/8
...
```

When the problem size reaches `1`:

[  
2^k=n  
]

so:

[  
k=\log_2n  
]

Number of leaves:

[  
3^k  
]

Substitute:

[  
3^{\log_2n}  
]

Therefore:

[  
n^{\log_23}  
]

So:

> **`n^(log_b a)` is simply the number of recursive leaves produced by repeatedly creating `a` children while shrinking each problem by factor `b`.**

# 21. Master Theorem and recursion-tree thinking

You should now connect the two.

Master Theorem:

```text
aT(n/b) + f(n)
```

Recursion tree:

```text
                    n
              /     |     \
            n/b    ...    n/b
           /               \
        n/b²              n/b²
```

Master Theorem's:

```text
n^(log_b a)
```

comes from:

```text
number of leaves
```

while:

```text
f(n)
```

represents:

```text
work performed by each node
```

Therefore the theorem is essentially answering:

> **Does the total work come primarily from the recursive leaves, equally from every level, or primarily from the upper-level local work?**

That is the conceptual core.

---

# 22. A subtle but important distinction: `O` vs `Θ`

When analyzing recurrences, you'll often see:

```text
O(n log n)
```

but mathematically the tighter result is:

```text
Θ(n log n)
```

The distinction:

```text
O(f(n))
```

means:

> grows no faster asymptotically than `f(n)`.

Whereas:

```text
Θ(f(n))
```

means:

> grows asymptotically at the same rate as `f(n)`.

For merge sort:

[  
T(n)=\Theta(n\log n)  
]

is the more precise statement.

---

# 23. Recursion depth and time are independent

Consider:

```text
T(n) = 2T(n/2) + n
```

Time:

```text
O(n log n)
```

Depth:

```text
O(log n)
```

Now:

```text
T(n) = T(n-1) + 1
```

Time:

```text
O(n)
```

Depth:

```text
O(n)
```

And:

```text
T(n) = 2T(n-1) + 1
```

Time:

```text
O(2^n)
```

Depth:

```text
O(n)
```

So there are two separate questions:

```text
How much total computation occurs?
```

and:

```text
How many recursive frames can exist simultaneously?
```

Never confuse them.

When reading recursive code, visualize it in this order:

```text
                 FUNCTION CALL
                      │
                      ↓
                current state
                      │
                      ↓
             identify problem size
                      │
                      ↓
              recursive transition
                      │
          ┌───────────┴───────────┐
          ↓                       ↓
      child state             child state
          │                       │
          ↓                       ↓
       recursive               recursive
          │                       │
          └───────────┬───────────┘
                      ↓
                   combine
                      │
                      ↓
                  return value
```

Then analyze:

```text
                    RECURSION TREE
                         │
            ┌────────────┼────────────┐
            ↓            ↓            ↓
       nodes/level   work/node      depth
            │            │            │
            └────────────┼────────────┘
                         ↓
                   TOTAL COMPLEXITY
```

This is the model you should carry into every recursive DSA problem.

# One final distinction before the next recursion pattern

At this point, we have studied **recursion as computation**:

```text
Function call
      ↓
Stack frame
      ↓
Recursive state
      ↓
Recursive tree
      ↓
Return / unwinding
      ↓
Result
```

Then we studied **recursion as a complexity structure**:

```text
Problem size
      ↓
Number of children
      ↓
Child problem size
      ↓
Tree depth
      ↓
Work per level
      ↓
Total complexity
```

The next pattern is fundamentally different: **Backtracking**.

There, recursive calls do not merely solve independent subproblems. Each call represents a **decision state**, modifies the current state, explores a branch, and then **restores the state during unwinding**:

```text
choose
  ↓
modify state
  ↓
recurse
  ↓
explore
  ↓
undo modification
  ↓
choose next option
```

That `choose → recurse → undo` state machine is the next major recursion pattern, and it is the foundation for problems such as **subsets, permutations, combination generation, N-Queens, Sudoku, and constraint search**.
