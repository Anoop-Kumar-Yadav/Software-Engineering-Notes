# Priority for Your Interview

Because you're targeting **backend/software roles**, don't distribute your time equally.

### Tier 1 — Master

**Must be interview-ready:**

- `var`, `let`, `const`
    
- Hoisting and TDZ
    
- Primitive vs reference types
    
- `==` vs `===`
    
- Truthy/falsy
    
- Arrays and objects
    
- `map`, `filter`, `reduce`
    
- Destructuring
    
- Spread/rest
    
- Functions
    
- Scope and closures
    
- `this`
    
- Prototypes
    
- Promises
    
- `async/await`
    
- Event loop
    
- Call stack
    
- Microtask vs macrotask
    
- `Promise.all`
    
- Error handling
    
- CommonJS vs ES Modules
    

### Tier 2 — Strongly Recommended

- `call`, `apply`, `bind`
    
- Classes
    
- Inheritance
    
- Generators
    
- Iterators
    
- Debouncing/throttling
    
- Currying
    
- Memoization
    
- Garbage collection
    
- Memory leaks
    
- JSON
    
- WeakMap/WeakSet
    

### Tier 3 — Don't Overinvest for Backend

- DOM manipulation
    
- Browser APIs
    
- CSS-related JavaScript
    
- Detailed browser rendering
    
- UI event handling
    

For your particular profile, **JavaScript runtime behavior is more valuable than DOM trivia**. If an interviewer asks you about Node.js, questions around the **event loop, Promises, closures, modules, asynchronous I/O, memory, and JavaScript execution model** are much more likely to connect with your backend work.

## Recommended Study Method

For each question, we'll use this format:

**Question → Interview answer → Technical explanation → Example → Common trap → Follow-up → Your turn**

For example:

> **Interviewer:** What is the difference between `var`, `let`, and `const`?

You first try to answer **out loud in simple English**. Then I'll correct your answer and give you a strong interview version. This also fits directly with the spoken-English interview practice you're doing.
